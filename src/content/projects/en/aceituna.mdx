## The problem

Getting the shopping ready scatters information across notes, memory and apps that do not know the shop. What you want to cook, what is missing at home and what you are about to spend live in different places.

## The solution

Aceituna keeps that whole path in one place. You create lists by occasion, add products from a catalogue of familiar brands and move them to the cart, which works out the total, what is pending and what is already bought. Each recipe keeps its ingredients and quantities, and is added to a list by scaling the servings without duplicating what you already had. The cooking assistant spots the ingredients you mention, finds matching recipes and works out what is missing.

## Technical decisions

Everything runs without external services: SQLite stores the data and the API loads a demo on start-up, without duplicating it on restart. That makes the app demo-ready in a minute at a hackathon. The assistant answers from the database when there is no AI key.

The interface applies optimistic updates, so ticking a product is instant even on a slow network. A single typed HTTP client talks to the API, which validates each request with Pydantic and splits its domains into routers. Fuzzy search tolerates the gap between what a person types and the catalogue name.

## Next steps

Users and shared lists with authentication, a per-environment CORS origin list, and moving SQLite behind an interface so PostgreSQL can replace it.
